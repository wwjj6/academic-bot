# 🏥 بوت المسابقات الأكاديمية — كلية الطب | جامعة حجة

بوت تيليجرام احترافي لإدارة المسابقات الأكاديمية بين طلاب كلية الطب، مبني بلغة Python باستخدام مكتبة `python-telegram-bot`.

---

## ✨ المميزات

### 🔹 نظام الأدوار (4 مستويات)

| الدور | الصلاحيات |
|---|---|
| 👑 **المشرف العام** | إدارة المدرسين، إدارة لجنة المسابقات، إدارة المقررات، التقارير الشاملة |
| 👨‍🏫 **المدرس** | مرتبط بعدة مقررات، إنشاء مسابقات وأسئلة لمقرراته، نتائج كل مقرر على حدة، إشعارات مستهدفة |
| 🧑‍⚖️ **لجنة المسابقات** | مراجعة أسئلة المدرسين قبل النشر، تعيين مقررات المدرسين، مسابقات عامة، الترتيب العام |
| 🎓 **الطالب** | التسجيل برقم جامعي، اختيار المقررات، المشاركة في مسابقات مقرراته |

### 🔹 ربط المدرس بالمقررات
- جدول وسيط `Professor_Subjects`: مدرس واحد ← عدة مقررات
- عند إنشاء مسابقة يختار المدرس المقرر من قائمة مقرراته المعتمدة فقط
- الإشعارات تُرسل **فقط** لطلاب المقرر المستهدف
- النتائج مفصولة حسب المقرر

### 🔹 المسابقات
- أنواع: 🗓 أسبوعية | 📅 شهرية | 🔥 تحديات ما قبل الامتحان | 🌐 عامة
- عدد الأسئلة: 5–50 سؤالاً (قابل للتعديل في `config.json`)
- أسئلة اختيار من متعدد (أ، ب، ج، د)
- جدولة تلقائية: تُفعَّل عند وقت البدء وتُغلق عند وقت الانتهاء تلقائياً
- مراجعة إلزامية من اللجنة قبل نشر مسابقات المدرسين

### 🔹 آلية المشاركة
- ⏳ عداد تنازلي لكل سؤال (انتهاء الوقت = إجابة خاطئة)
- سؤال واحد في كل مرة — **لا رجوع للخلف**
- 🔒 إغلاق تلقائي للمسابقة عند وقت الانتهاء
- 📊 نتيجة فورية + ترتيب أفضل 10 (Top 10)
- 🏆 لوحة ترتيب عامة ولكل مقرر (نقاط تراكمية)

### 🔹 واجهة الاستخدام
- 🎛 لوحة أزرار دائمة بجانب حقل الكتابة (القائمة الرئيسية، التعليمات، الترتيب العام)
- ☰ زر قائمة الأوامر الرسمي بجوار حقل الإدخال
- 📖 تعليمات استخدام مخصصة لكل دور تظهر عند `/start` و `/help`
- 🏆 رسالة ترحيب رسمية باسم اللجنة العلمية

## 🛠 الدليل الكامل: إنشاء البوت من الصفر

### الخطوة 1 — إنشاء البوت في تيليجرام (BotFather)

1. افتح تيليجرام وابحث عن [@BotFather](https://t.me/BotFather) (البوت الرسمي الموثق ✔️ من تيليجرام — تأكد من علامة التوثيق)
2. أرسل الأمر:
   ```
   /newbot
   ```
3. أرسل **اسم البوت** المعروض (يقبل العربية)، مثال:
   ```
   المسابقات الأكاديمية - كلية الطب | جامعة حجة
   ```
4. أرسل **اسم المستخدم** للبوت — يجب أن ينتهي بـ `bot` وبالأحرف الإنجليزية، مثال:
   ```
   HU_2_levelbot
   ```
5. سيرد BotFather برسالة تهنئة تحتوي **توكن البوت** بصيغة مشابهة لـ:
   ```
   1234567890:AAAbbbCCCdddEEEfffGGGhhhIIIjjjKKKll
   ```
   ⚠️ **هذا التوكن هو مفتاح السيطرة الكاملة على البوت — انسخه ولا تشاركه مع أحد أبداً** (انظر قسم الأمن والحماية أدناه).

6. إعدادات اختيارية مُستحسنة من BotFather:
   | الأمر | الوظيفة |
   |---|---|
   | `/setdescription` | وصف يظهر قبل بدء المحادثة |
   | `/setabouttext` | نبذة في صفحة البوت |
   | `/setuserpic` | صورة البوت الشخصية |
   | `/setprivacy` → `Disable` | ليس مطلوباً هنا (البوت يعمل بالخاص) |

### الخطوة 2 — تجهيز بيئة التشغيل

1. ثبّت [Python 3.9 أو أحدث](https://www.python.org/downloads/) (أو استخدم أناكوندا)
2. حمّل المشروع:
   ```bash
   git clone https://github.com/hazeemcs/Telegram_bot.git
   cd Telegram_bot
   ```
3. ثبّت المكتبات:
   ```bash
   pip install -r requirements.txt
   ```

### الخطوة 3 — ملف الإعدادات

انسخ النموذج ثم عدّله (ملف `config.json` **لا يُرفع** إلى GitHub أبداً):
```bash
copy config.example.json config.json     # ويندوز
cp config.example.json config.json       # لينكس/ماك
```

افتح `config.json` وعدّل:
```json
{
    "bot_token": "التوكن_الذي_أعطاك_إياه_BotFather",
    "admin_ids": [123456789],
    "admin_usernames": ["username1", "username2"]
}
```

| الحقل | الشرح |
|---|---|
| `bot_token` | توكن البوت من BotFather (الخطوة 1) |
| `admin_ids` | المعرفات **الرقمية** للمشرفين — الطريقة الأكثر أماناً. احصل على معرفك من [@userinfobot](https://t.me/userinfobot) |
| `admin_usernames` | أسماء مستخدمين تُمنح صلاحية المشرف عند أول `/start` (بدون @) — طريقة مساعدة عندما لا تعرف المعرف الرقمي |
| `min_questions` / `max_questions` | حدود عدد أسئلة المسابقة (افتراضياً 5–50) |
| `top_n_leaderboard` | عدد المراكز في لوحة الترتيب (افتراضياً 10) |

### الخطوة 4 — التشغيل

```bash
python bot.py
```

على ويندوز مع أناكوندا:
```
C:\ProgramData\anaconda3\python.exe bot.py
```

عند نجاح التشغيل سترى في السجل:
```
✅ قاعدة البيانات جاهزة.
🚀 بوت المسابقات الأكاديمية يعمل الآن...
✅ فُعّل زر القائمة (☰) بجانب حقل الكتابة.
Application started
```

> 💡 **للتشغيل الدائم**: اترك نافذة الأوامر مفتوحة، أو استخدم أداة مثل `NSSM` على ويندوز أو `systemd` على لينكس لتشغيل البوت كخدمة تعمل تلقائياً عند إقلاع الجهاز.

### الخطوة 5 — الإعداد الأولي داخل البوت (بالترتيب)

1. **المشرف العام** يرسل `/start` ← تظهر لوحة المشرف
2. يضيف **المقررات** من (📚 إدارة المقررات)
3. يضيف **المدرسين** بمعرفاتهم الرقمية من (👨‍🏫 إدارة المدرسين)
4. يضيف **أعضاء اللجنة** من (🧑‍⚖️ إدارة لجنة المسابقات)
5. **اللجنة** تعين مقررات كل مدرس من (🔗 تعيين مقررات المدرسين)
6. **الطلاب** يسجلون أنفسهم بـ `/start` ← الرقم الجامعي ← الاسم ← اختيار المقررات
7. **المدرسون** ينشئون المسابقات ← اللجنة تعتمد ← كل ما بعدها تلقائي

## 📖 دليل الاستخدام السريع

### المشرف العام
1. أرسل `/start` — تظهر لوحة المشرف تلقائياً (معرفك في `admin_ids`)
2. أضف المقررات من **📚 إدارة المقررات**
3. أضف المدرسين وأعضاء اللجنة بمعرفات تيليجرام الخاصة بهم

### لجنة المسابقات
1. **🔗 تعيين مقررات المدرسين** — اربط كل مدرس بمقرراته
2. **🔍 مراجعة مسابقات المدرسين** — اعتماد أو رفض قبل النشر
3. **🌐 إنشاء مسابقة عامة** — تُنشر بدون مراجعة

### المدرس
1. **➕ إنشاء مسابقة جديدة** — اختر المقرر ← الاسم ← النوع ← عدد الأسئلة ← المدة ← المواعيد ← أدخل الأسئلة
2. تُرسل تلقائياً للجنة للمراجعة، وعند الاعتماد تُجدول وتُفعَّل تلقائياً
3. **📊 نتائج الطلاب** — مفصولة حسب كل مقرر
4. **📢 إرسال إشعار** — يصل فقط لطلاب المقرر المحدد

### الطالب
1. `/start` ← أدخل الرقم الجامعي ← الاسم ← اختر مقرراتك
2. عند بدء أي مسابقة لمقرراتك يصلك إشعار بزر **🚀 ابدأ المسابقة الآن**
3. أجب على الأسئلة قبل انتهاء العداد — النتيجة والترتيب يظهران فوراً

## 🔐 الأمن والحماية — التعامل الصحيح مع التوكنات

### ⚠️ لماذا التوكن خطير؟
توكن البوت = **السيطرة الكاملة** على البوت: من يحصل عليه يستطيع قراءة رسائل المستخدمين للبوت، وإرسال رسائل باسمه، وحذف بياناته، وانتحال هوية الكلية أمام الطلاب. توكن GitHub = الوصول إلى مستودعاتك بحسب صلاحياته.

### 1️⃣ القواعد الذهبية لتوكن البوت

| ✅ افعل | ❌ لا تفعل |
|---|---|
| احفظه في `config.json` فقط (مستثنى من Git) | لا تكتبه داخل ملفات الكود `.py` أبداً |
| شاركه مع مسؤول واحد موثوق عند الضرورة عبر قناة خاصة | لا ترسله في مجموعات أو قنوات أو لقطات شاشة |
| جدّده دورياً (كل عدة أشهر) | لا ترفعه إلى GitHub حتى في مستودع خاص |
| تحقق من `git status` قبل كل `commit` | لا تحفظه في ملفات نصية داخل مجلد المشروع بدون استثنائه |

### 2️⃣ ماذا تفعل إذا تسرب توكن البوت؟ (خطوات فورية)

1. افتح [@BotFather](https://t.me/BotFather) فوراً
2. أرسل `/mybots` ← اختر البوت ← **API Token** ← **Revoke current token**
   (أو الأمر المباشر: `/revoke`)
3. سيلغي BotFather التوكن القديم **نهائياً** ويعطيك توكناً جديداً
4. ضع التوكن الجديد في `config.json` وأعد تشغيل البوت
5. التوكن المسرب أصبح عديم الفائدة — لا يمكن لأحد استخدامه

> 💡 إعادة التوليد لا تؤثر على بيانات البوت أو مستخدميه — فقط المفتاح يتغير.

### 3️⃣ توكن GitHub (لرفع الكود)

استخدم **Fine-grained Personal Access Token** وليس التوكن الكلاسيكي:

1. GitHub ← **Settings** ← **Developer settings** ← **Fine-grained personal access tokens** ← **Generate new token**
2. طبّق مبدأ **أقل صلاحية ممكنة**:
   - **Repository access**: `Only select repositories` ← اختر مستودع البوت فقط
   - **Permissions** ← **Contents**: `Read and write` — وهذا كل ما يلزم للدفع (push)
   - لا تمنح صلاحيات إضافية (Issues, Actions, Admin...) لا تحتاجها
3. حدد **تاريخ انتهاء** قصيراً (30–90 يوماً) وجدّده عند الحاجة
4. عند التسريب: **Settings** ← **Developer settings** ← التوكن ← **Delete** فوراً، ثم أنشئ توكناً جديداً

> ⚠️ خطأ شائع: توكن بصلاحية قراءة فقط (بدون `Contents: Read and write`) يستطيع `clone` لكن يفشل `push` بخطأ 403 "Write access not granted".

### 4️⃣ حماية المشروع تلقائياً (`.gitignore`)

الملفات التالية **مستثناة من الرفع** ولن تصل إلى GitHub أبداً:

```
API_Token              # توكن GitHub
Bot_information.md     # بيانات البوت وتوكنه من BotFather
config.json            # الإعدادات الفعلية (توكن البوت + معرفات المشرفين)
*.db                   # قاعدة البيانات (بيانات الطلاب والنتائج)
*.env / .env           # أي ملفات متغيرات بيئة
```

يُرفع فقط `config.example.json` (نموذج بقيم وهمية) — وقبل أي `commit` تحقق دائماً:
```bash
git status          # تأكد أن الملفات الحساسة لا تظهر في القائمة
```

### 5️⃣ إذا رُفع توكن إلى GitHub بالخطأ

حذف الملف في commit جديد **لا يكفي** — التوكن يبقى في تاريخ Git وتفحصه روبوتات آلياً خلال دقائق:
1. **ألغِ التوكن فوراً** (الخطوة 2 أو 3 أعلاه) — هذا هو الإجراء الحاسم
2. ثم نظّف التاريخ إن لزم (`git filter-repo`) أو احذف المستودع وأعد إنشاءه

### 6️⃣ توصيات إضافية

- **المشرفون بالمعرف الرقمي أفضل من اسم المستخدم**: اسم المستخدم يمكن تغييره وقد يستولي عليه شخص آخر، بينما المعرف الرقمي ثابت مدى الحياة. استخدم `admin_usernames` مؤقتاً فقط، ثم انقل المعرفات الرقمية إلى `admin_ids`
- **انسخ قاعدة البيانات احتياطياً** (`academic_bot.db`) دورياً — تحوي كل الطلاب والنتائج
- شغّل البوت بحساب مستخدم عادي (ليس بصلاحيات المدير/root)
