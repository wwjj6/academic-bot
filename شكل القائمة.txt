
1️⃣ القائمة الرئيسية السفلية → Reply Keyboard

ReplyKeyboardMarkup([...], resize_keyboard=True)
الأزرار الثابتة أسفل شاشة الدردشة («📢 الإعلانات»، «❓ الأسئلة»…). تُرسل نصاً عادياً عند الضغط، ويلتقطها موجّه (menu_router) يحوّل النص إلى الدالة المناسبة — وهذا يُسمّى نمط Menu Router / Dispatcher.

2️⃣ لوحة التحكم /admin → Nested Inline Menus (القوائم المتداخلة بتحرير الرسالة)
وهذا هو الأسلوب المميز في اللوحة، ويقوم على فكرتين:

Inline Keyboard (InlineKeyboardMarkup): أزرار ملتصقة بالرسالة نفسها.
Single-Message Navigation: بدل إرسال رسالة جديدة لكل شاشة، نستخدم edit_message_text فتتبدّل «الشاشات» داخل رسالة واحدة — كأنها تطبيق كامل داخل رسالة. الرجوع للخلف مجرد تحرير آخر.
3️⃣ توجيه الأزرار → Callback Data Prefix Routing
كل زر يحمل بيانات على شكل قسم:إجراء:معرّف مثل:


stu:ban:123   ann:view:5   aq:approve:7
ومعالِجات CallbackQueryHandler تلتقطها بأنماط Regex (^stu:ban:\d+$). هذا نمط توجيه هرمي يشبه مسارات الويب (routes) لكن داخل تلغرام.

4️⃣ المحادثات متعددة الخطوات → FSM (آلة الحالات المحدودة)
التسجيل، طرح سؤال، إنشاء إعلان… كلها مبنية على ConversationHandler وهو تطبيق لنمط Finite State Machine: كل خطوة «حالة» (اكتب الاسم ← اختر السنة ← أدخل الرقم)، والانتقال بينها محكوم، مع مخرج /cancel من أي حالة.

5️⃣ إظهار الأزرار حسب الدور → Permission-Gated Menus
القائمة لا تُبنى ثابتة، بل يُفحص كل زر بـ can(user, Perm.X) قبل إضافته — فالمراقب يرى قائمة أقصر من المشرف العام، من نفس الكود.
